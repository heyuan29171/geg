# geg

纯静态 HTML 挂机集卡小游戏。零依赖，无需构建，直接双击 `index.html` 即可运行。

## 玩法

- 自动与怪物战斗，击杀怪物掉落一张随机卡片。
- 每张卡片有唯一编号（NO.xxx）和稀有度：白 < 绿 < 蓝 < 紫 < 金 < 红 < 黑 < 炫彩。
- 每张卡片有一个**需求编队**：编队按**已拥有成员**出战（成员越多越强，编队可以只有自己，一般不超过 10 张），集齐后全员上阵发挥完整战力。
- 战力 = Σ已拥有成员基础战力 ×（1 + 0.2×(n−1) + 0.05×(n−1)²），n = 已拥有成员数。集齐前战力随收集进度平滑增长（如纯绿队集 2 张就有 28 战力，高于初始 6 蛋队 19.5），集齐后即全员公式。
- 战斗间隔由出战编队战力决定：间隔 = 10s ×（初始战力 / 当前战力）^0.4956，指数按"创世神编队 0.02 秒一场（50 抽/秒）"标定。初始六蛋约 10 秒一场，绿卡编队约 5-6 秒，蓝卡约 3-4 秒，紫卡约 2.7 秒，金卡约 1.6-2 秒，红卡约 0.18 秒，黑卡约 0.05 秒。**编队越难凑齐（成员越多）战力越高、抽得越快，同稀有度内拉开差距；任何编队都不会超过创世神。**
- 重复卡片自动转化为**碎片**，10 碎片可立即出战一次，也可以一键把所有碎片全部用于抽卡。
- 离线收益：关闭页面后，按线上抽卡速度的 1/10 折算为碎片发放，最多累积 8 小时。
- 图鉴与背包支持按编号 / 稀有度 / 战力 / 编队战力（背包另有持有数）排序，可切换升序降序。
- 图鉴与背包支持组合筛选：稀有度 × 获得状态 × 编队状态（可出战/未集齐）× 战力区间 × 名称搜索。

## 存档与数据隔离

- 存档保存在浏览器 localStorage（键名 `geg_save_v1`），与游戏代码完全隔离；导出/导入为乱码编码格式，带校验和，损坏文件会被拒绝。
- 重置存档需连点两次按钮确认；重置/导入后旧页面的自动保存不会把数据写回去。
- 同一浏览器下多个副本共享同一份存档。如需完全独立的存档（如测试不同配置），在网址后加 `?save=名字`（如 `index.html?save=test`），每个名字对应一套独立存档键 `geg_save_v1_名字`，导出文件名也会带上名字。
- 存档格式带版本号（`v:1`），版本不匹配的旧数据会被忽略、以全新初始存档开局。

## 初始卡片

初始赠送六张白卡：金蛋、木蛋、水蛋、火蛋、土蛋、炫彩蛋。炫彩蛋的需求编队正是另外五颗蛋。**炫彩蛋每个账号仅一张（unique），获得后不会再次掉落。**

## 掉落概率（无保底，纯随机）

| 稀有度 | 单抽概率 | 期望抽数 | 基础战力 | 重复→碎片 |
| --- | --- | --- | --- | --- |
| 白卡 | 55% | 1.8 抽 | 1 | 1 |
| 绿卡 | 30% | 3.3 抽 | 10 | 3 |
| 蓝卡 | 10% | 10 抽 | 20 | 8 |
| 紫卡 | 2% | 50 抽 | 45 | 25 |
| 金卡 | 0.4% | 250 抽 | 107 | 80 |
| 红卡 | 0.004% | 2.5 万抽 | 12000 | 118211 |
| 黑卡 | 0.0001% | 100 万抽 | 80000 | 4058505 |
| 炫彩卡 | 0.00002% | 500 万抽 | 2000000 | 24351030 |

说明：红卡及以上的重复转化碎片 = 期望抽数 ÷ 4 × 20，即 4 张重复 ≈ 期望抽到该阶及以上的抽数。期望时间取决于抽卡速度——金卡编队（30 抽/分）下红卡约 14 小时；创世神编队（50 抽/秒）下红卡约 8 分钟、黑卡约 5.6 小时、炫彩约 1.2 天。

图鉴中金卡及以上（金/红/黑/炫彩）在未获得前保持神秘（不显示名字与编号），获得后才解锁。

## 目录结构

```
geg/
├── index.html          入口页
├── css/style.css       样式（白底简约风）
├── js/
│   ├── data.js         数值与卡片定义（加新卡改这里）
│   ├── save.js         存档读写（localStorage）
│   ├── game.js         战斗 / 掉落 / 编队战力逻辑
│   ├── ui.js           界面渲染 / 图鉴 / 背包 / 3D 观赏
│   └── main.js         启动与事件绑定
└── img/
    ├── cards/          卡片图（png 命名见下方）
    └── monsters/
        ├── monster.svg 占位怪物
        └── monster.png 放自己的怪物图（可选）
```

## 添加新卡片

在 `js/data.js` 的 `CARDS` 数组**末尾**追加，编号自动按顺序生成，不会抢占已有编号：

```js
{ id: 'new-card-id',            // 唯一 id，同时是图片文件名
  name: '新卡名字',
  rarity: 'green',              // white/green/blue/purple/gold/red/black/rainbow
  unique: false,                // true 表示全账号唯一，获得后不再掉落
  art: { type: 'emoji', emoji: '🐣' },   // 或 { type: 'egg', colors: [...] }
  desc: '卡片描述',
  flavor: '一句话彩蛋文案',
  formation: ['egg-wood', 'sapling'] }   // 需求编队成员 id，可留空 []
```

## 美术资源

- 卡片图：`img/cards/<卡片id>.png`，放进去自动替换占位图（id 对照表见 `img/cards/README.md`）。
- 怪物图：`img/monsters/monster.png` 替换占位怪物。
- 六颗蛋为 CSS 绘制占位，其余卡片为 emoji 占位，均可被 png 覆盖。

## 存档

- 存档保存在浏览器 localStorage（键 `geg_save_v1`），**不写入任何文件，与游戏代码完全隔离**，不会进 git。
- 设置页可导出 / 导入 / 重置存档。导出文件为乱码编码格式（带魔数与 XOR 混淆），导入时校验，防止玩家直接改存档；被修改或损坏的存档会被拒绝导入。
- 换浏览器、清理缓存前请先导出。

## 部署到 GitHub Pages

1. 推到 GitHub 仓库。
2. 仓库 Settings → Pages → Source 选 `Deploy from a branch` → 分支 `main` → 目录 `/ (root)`。
3. 访问 `https://<用户名>.github.io/<仓库名>/`。

本地预览也可用 `python -m http.server` 或任意静态服务器。
