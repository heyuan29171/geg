# geg

一个零依赖的挂机集卡小游戏，`index.html` 双击就能玩。

- 当前版本：**v1.3.6**
- 在线游玩：https://heyuan29171.github.io/geg/
- GitHub 仓库：https://github.com/heyuan29171/geg

## 玩家指南

### 玩法

- 自动与怪物战斗，击杀掉落一张随机卡片，编号 NO.001 起。
- **新手教程**：全新存档会弹出强引导，教你点击怪物抽卡、用碎片抽卡、按编队战力换上最强编队，最后带你去设置页看说明；可随时跳过，不会卡住游戏。
- 稀有度：白 < 绿 < 蓝 < 紫 < 金 < 红 < 黑 < 炫彩。金卡及以上未获得前，图鉴中保持神秘（不显示名字与编号）。
- 每张卡有**需求编队**：编队按已拥有成员出战（成员越多越强，可只有自己，一般不超过 10 张），集齐后全员上阵。
- 战力 = Σ已拥有成员基础战力 ×（1 + 0.2×(n−1) + 0.05×(n−1)²），n = 已拥有成员数。集齐前战力随收集进度增长，集齐后为完整编队战力。
- 战斗间隔 = 10s ×（初始蛋队 13 战力 / 当前战力）^0.4956，最短 0.005s。初始六蛋约 10 秒一场，绿卡编队约 5-6 秒，蓝卡约 3-4 秒，紫卡约 2.7 秒，金卡约 1.6-2 秒，红卡约 0.18 秒，黑卡约 0.05 秒。编队越难凑齐战力越高、抽得越快；任何编队不超过创世神（约 0.016 秒一场）。
- 重复卡片自动转**碎片**，10 碎片 = 1 抽；一键用全部碎片抽卡（单次最多 5000 抽）。
- 碎片规则：白 1 / 绿 2；蓝及以上 = 该稀有度期望抽数 × 0.65。平均每抽回本约一半，抽完全部碎片后约剩一半。
- 离线收益：关闭页面或切走标签页期间，按线上抽卡速度的 1/10 折算为碎片，最多累计 8 小时，回到页面自动入账。
- 点击怪物：每次缩短下一抽 0.5 秒。
- **防老板模式**：按 `Tab` 键把整个页面伪装成记事本（可正常打字），挂机信息（抽速/碎片/新卡）显示在底部状态栏，可用「上最强」「抽碎片」一键操作；再按 `Tab` 或 `Esc` 恢复。深色模式在设置页切换，自动保存。
- 图鉴与背包支持排序（编号 / 稀有度 / 战力 / 编队战力，背包另有持有数与获得时间）与组合筛选（稀有度 × 获得状态 × 编队状态 × 战力区间 × 名称搜索）。获得时间 = 该卡首次获得的时间，初始赠送的卡以开局时间为准。

### 初始卡片

初始赠送六张白卡：金蛋、木蛋、水蛋、火蛋、土蛋、炫彩蛋。炫彩蛋的编队正是另外五颗蛋，每个账号仅一张，获得后不再掉落。

### 掉落概率（无保底，纯随机）

| 稀有度 | 单抽概率 | 期望抽数 | 基础战力 | 重复→碎片 |
| --- | --- | --- | --- | --- |
| 白卡 | 84.1% | 1.2 抽 | 1 | 1 |
| 绿卡 | 11.2% | 9 抽 | 10 | 2 |
| 蓝卡 | 3.82% | 26.2 抽 | 20 | 17 |
| 紫卡 | 0.76% | 131 抽 | 45 | 85 |
| 金卡 | 0.15% | 654 抽 | 107 | 425 |
| 红卡 | 0.0061% | 1.6 万抽 | 12000 | 10628 |
| 黑卡 | 0.0002% | 54.5 万抽 | 80000 | 425127 |
| 炫彩卡 | 0.00003% | 327 万抽 | 2000000 | 2125634 |

期望时间取决于抽卡速度：6 蛋队（10 秒/抽）下第一张绿卡约 90 秒、蓝卡约 4.4 分钟、紫卡约 22 分钟、金卡约 1.8 小时；金卡编队（30 抽/分）下红卡约 9 小时；创世神编队（61 抽/秒）下红卡约 4.5 分钟、黑卡约 3 小时、炫彩约 15 小时。

### 存档

- 存档保存在浏览器本地，不会上传到任何服务器。换浏览器或清理缓存前，先导出存档。
- 设置页可导出 / 导入 / 重置存档（重置需连点两次确认）。
- 同一浏览器下多个页面共用一份存档；需要独立存档时，在网址后加 `?save=名字`（如 `index.html?save=test`）。

## 开发者指南

### 目录结构

```
geg/
├── index.html          入口页
├── css/style.css       样式（白底简约风）
├── js/
│   ├── data.js         数值与卡片定义（加新卡改这里）
│   ├── save.js         存档读写（localStorage）
│   ├── game.js         战斗 / 掉落 / 编队战力逻辑
│   ├── ui.js           界面渲染 / 图鉴 / 背包 / 3D 观赏
│   ├── tutorial.js     新手教程（强引导状态机）
│   └── main.js         启动与事件绑定
├── tools/
│   ├── gen-cards-readme.js  从 data.js 生成 img/cards/README.md
│   └── batch_gen.py         本地 Stable Diffusion 批量生成卡片图（需 GPU/Python）
└── img/
    ├── cards/          卡片图（png 命名见下方）
    └── monsters/
        ├── monster.svg 占位怪物
        └── monster.png 放自己的怪物图（可选）
```

### 添加新卡片

在 `js/data.js` 的 `CARDS` 数组**末尾**追加，编号自动按顺序生成，不会抢占已有编号：

```js
{ id: 'new-card-id',            // 唯一 id，同时是图片文件名
  name: '新卡名字',
  rarity: 'green',              // white/green/blue/purple/gold/red/black/rainbow
  unique: false,                // true 表示全账号唯一，获得后不再掉落
  art: { type: 'emoji', emoji: '🐣' },   // 或 { type: 'egg', colors: [...] }
  desc: '卡片描述',
  flavor: '一句话彩蛋文案',
  formation: ['egg-wood', 'sapling'] }   // 需求编队成员 id，可留空 []
```

加完新卡后运行 `node tools/gen-cards-readme.js` 重新生成 `img/cards/README.md`（含全部卡片的编队、描述与彩蛋文案），并按「开发约定」更新版本号与更新日志。

### 美术资源

- 卡片图：`img/cards/<卡片id>.png`，放进去自动替换占位图（id 对照表见 `img/cards/README.md`）。
- 怪物图：`img/monsters/monster.png` 替换占位怪物。
- 六颗蛋为 CSS 绘制占位，其余卡片为 emoji 占位，均可被 png 覆盖。

### 存档格式

- localStorage 键名 `geg_save_v1`（`?save=名字` 时为 `geg_save_v1_名字`），与游戏代码完全隔离，不会进 git。
- 导出文件为乱码编码（魔数 + XOR 混淆 + 校验和），导入时校验，被修改或损坏的存档会被拒绝。
- 存档带版本号 `v:1`，版本不匹配的旧数据会被忽略，以全新初始存档开局。

### 部署到 GitHub Pages

1. 推到 GitHub 仓库。
2. 仓库 Settings → Pages → Source 选 `Deploy from a branch` → 分支 `main` → 目录 `/ (root)`。
3. 访问 `https://<用户名>.github.io/<仓库名>/`。

本地预览可用 `python -m http.server` 或任意静态服务器。

### 开发约定

每次改动必须同步：

1. **版本号**：递增 `js/data.js` 中 `CONFIG.VERSION`（修复 +0.0.1，新功能 +0.1.0，大版本 +1.0.0），设置页自动显示。
2. **更新日志**：在文末「更新日志」顶部追加一行（版本号、日期、一句话摘要）。
3. **卡片文档**：卡片数据变动时运行 `node tools/gen-cards-readme.js` 重新生成 `img/cards/README.md`。
4. 推送 `main` 分支自动部署到 GitHub Pages。
